# Known issues и план работ

Этот файл — список проблем, обнаруженных при доработке проекта
(SFML-сборка, запуск из `build`, ревью кода). Часть из них уже
исправлена в текущей ветке, часть остаётся на будущее.

Легенда приоритетов:
- **[P1]** — баг/риск, влияет на корректность или стабильность;
- **[P2]** — ухудшение, не блокирует работу;
- **[P3]** — рефакторинг/улучшение, не влияет на текущее поведение.

---

## Уже исправлено в этой ветке

- [x] **Сборка SFML из исходников (Windows + Linux).** Раньше нужны
  были предкомпилированные библиотеки SFML 2.5, которые не подходили
  по ABI к современному компилятору (падение `0xC0000139`). Теперь
  `setup-*.bat/sh` скачивают исходники и собирают SFML статически
  тем же компилятором. (`setup-windows.bat`, `setup-linux.sh`)
- [x] **Загрузка шрифтов/иконки из любого каталога.** Раньше ресурсы
  искались относительно рабочей папки; при запуске `solver.exe` из
  `build` тексты не отображались. Теперь — сначала рядом с
  исполняемым файлом, потом в `resources/`.
  (`source/app.h`, `source/tools.h`)
- [x] **Некорректные указатели на методы в `sf::Thread`.**
  `new sf::Thread(method, this)` не компилировался современным GCC;
  добавлены `&App::` и `this`. (`source/app.h`)
- [x] **Ложные сообщения `Failed to load font/image`** в консоли при
  переборе путей ресурсов. Добавлена проверка существования файла до
  загрузки. (`source/tools.h`)
- [x] **Документация по сборке и использованию.**
  (`README.md`, `USAGE.md`)

## Осталось исправить (по приоритету)

### [P1] `App::loadConfig` — загрузка конфигурации ненадёжна
Файл: `source/app.h` (`App::loadConfig`, ~строка 637).

Что происходит:
- из файла читаются `gridSize`, `cellSize`, `fieldSize`, но **не
  пересоздаются** `grid`, `XcumsumGrid`/`YcumsumGrid`, не обновляются
  `fieldTexture`, `fieldSprite`, `rangeInfo`;
- если размер сетки в файле отличается от текущего (150×150),
  происходит обращение `grid.at(j)` за пределами вектора → падение;
- если размер совпал, поиск идёт по устаревшим префиксным суммам →
  неверный результат.

Что нужно сделать:
- пересоздавать `grid` по размеру из файла;
- пересчитывать `XcumsumGrid`/`YcumsumGrid`;
- обновлять `fieldTexture.create(...)`, `fieldSprite.setTexture/Scale`,
  текст `rangeInfo`;
- восстанавливать маркеры и параметры (уже частично есть);
- добавить проверку размера/корректности файла перед чтением.

### [P1] ПКМ понижает рельеф даже при выключенном «Change grid»
Файл: `source/app.h` (`App::eventHandler`, ~строка 529).

Что происходит:
```cpp
if (changeFieldSwitch->isOn && sf::Mouse::isButtonPressed(sf::Mouse::Left) ||
    sf::Mouse::isButtonPressed(sf::Mouse::Right)) {
```
из-за приоритета `&&` выше `||` правая кнопка действует независимо от
переключателя: пользователь может случайно «понизить» рельеф, просто
кликнув ПКМ вне поля.

Что нужно сделать: обернуть условие скобками:
```cpp
if (changeFieldSwitch->isOn &&
    (sf::Mouse::isButtonPressed(sf::Mouse::Left) ||
     sf::Mouse::isButtonPressed(sf::Mouse::Right))) {
```

### [P1] Фоновые потоки завершаются `terminate()` и пишут в UI без синхронизации
Файл: `source/app.h` (конструктор/`run`/деструктор, `sf::Thread`).

Что происходит:
- `thread->terminate()` в деструкторе — принудительное завершение
  потока в произвольный момент; при закрытии окна во время расчёта
  это может привести к UB/зависанию;
- фоновые потоки пишут в `workInfo` (`sf::Text`) и `diff`, а главный
  поток их читает — data race;
- потоки создаются в `init()` и не проверяются на «запущен ли».

Что нужно сделать:
- заменить `sf::Thread` на `std::thread` + `std::atomic<bool> stop`;
- в цикле фоновой работы проверять флаг завершения;
- вызывать `join()` в деструкторе/перед закрытием окна;
- прогресс передавать через `std::atomic<float>`/`std::mutex`,
  обновлять UI только в главном потоке.

### [P2] `TextBox::InputText` — кириллица искажается и читается `event.key.control` без проверки типа
Файл: `source/tools.h` (`TextBox::InputText`, ~строка 857).

Что происходит:
- `event.key.control` читается для любого типа события — в SFML
  `event.key` это union, поведение не определено;
- кириллица («rus» через `setlocale`) преобразуется в ASCII-коды и
  отображается неверно.

Что нужно сделать:
- проверять `event.type == sf::Event::KeyPressed` перед чтением
  `event.key`;
- для TextEntered использовать `sf::String`/`wchar_t` и `sf::Text`
  с поддержкой Unicode (например, конвертация в UTF-8 для `sf::Text`
  в SFML 2.5, либо перейти на SFML 3);
- либо явно ограничить ввод латиницей и сообщить об этом в UI.

### [P2] `MultiSlider` — утечка `sf::Texture`
Файл: `source/tools.h` (`MultiSlider::MultiSlider`, ~строка 730).

Что происходит: `new sf::Texture()` создаётся и передаётся
`background.setTexture(texture)`, но текстура нигде не хранится и не
удаляется.

Что нужно сделать: хранить `sf::Texture` как член класса (или
`std::unique_ptr`), удалять в деструкторе.

## Рефакторинг (P3) — по желанию, отдельным PR

### 1. Разнести `.h` → `.cpp`
Сейчас вся реализация (`App`, виджеты, геометрия) находится в
`source/app.h` (~1600 строк) и `source/tools.h` (~900 строк), а
компилируется только `main.cpp`. Это:
- замедляет компиляцию (любая правка — перекомпиляция всего);
- усложняет навигацию по коду.

План: объявления в `app.h`/`tools.h`, реализации в `app.cpp`/`tools.cpp`
(+ возможно `widgets.cpp`, `geometry.cpp`), `main.cpp` остаётся точкой
входа.

### 2. Убрать глобальные переменные
- `XcumsumGrid`, `YcumsumGrid` — префиксные суммы поля;
- `leftC`, `rightC` — промежуточные значения границ;
- `arialFont`, `consolaFont` — шрифты.

Все эти значения логично сделать членами `App` (или передавать
параметрами), тогда `loadConfig`/`loadField` не будут зависеть от
глобального состояния (связано с P1: loadConfig).

### 3. Удалить/вернуть мёртвый код
Сейчас к интерфейсу подключены только **DP Method** и
**Full Walk Method**. Не используются:
- `PickButton` (класс);
- `calculateOptimalSolutionWithFullFieldWalk()` (Method 0);
- `calculateOptimalSolutionByApproxWithRect()` (Method 1);
- `calculateOptimalSolutionByAngle()` (Method 4);
- `makeExperiment()` и кнопка **Experiment**;
- `threadApproxRect`, `threadExperiment` и их инициализация/удаление.

Варианты: удалить полностью, либо оставить и подключить к кнопкам
(сейчас кнопки Method 1/Experiment скрыты).

### 4. Уменьшить дублирование в методах поиска
Методы 0/1/3/4 почти копируют друг друга (~200 строк каждый) с
одинаковыми `goto doStep`, обходом `path` и пересчётом границ.
Можно вынести общий скелет перебора (walk/backtrack) и отличающиеся
части (ограничения, вычисление прогресса). **Важно**: делать это
аккуратно и проверять на `test.cfg` (результаты должны совпасть с
эталонными: `start (32,22) → turn1 (96,20) → turn2 (125,49) →
end (122,114)`, difficulty ≈ 93.635).

### 5. Прочее
- `CMakeLists.txt`: `cmake_minimum_required(VERSION 3.10)` расходится
  с README (`>= 3.16`) — выровнять;
- неиспользуемые переменные/предупреждения компилятора
  (`corner`, `leftSize`, `cosOfMaxAngle`, `sinOfMaxAngle` и т.п.);
- в `App::init()` кнопки `Method 1`/`Experiment` создаются, но не
  отрисовываются — либо убрать, либо вернуть;
- при переносе `solver.exe` без `arial.ttf`/`consola.ttf`/`mai.png`
  рядом текст не отобразится — добавить в документацию явный
  «minimal distribution» (что копировать);
- при открытии/загрузке файлов нет сообщения об ошибке (тихий
  `return`, если файл не найден) — стоит выводить в UI/консоль.
