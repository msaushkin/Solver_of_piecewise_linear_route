# Руководство пользователя: Solver piecewise linear route

В этом документе описано, как пользоваться приложением: расположение и
назначение всех элементов интерфейса, порядок действий и примеры.

## 1. Запуск

Windows:

```bat
setup-windows.bat      :: один раз, если ещё не собирали SFML
compile-windows.bat    :: сборка build\solver.exe
build\solver.exe       :: запуск
```

Linux:

```bash
./setup-linux.sh       # один раз, если ещё не собирали SFML
./compile-linux.sh     # сборка build/solver
./build/solver         # запуск
```

> **Важно.** Программа ищет шрифты и иконку **рядом с исполняемым
> файлом** (`build/`), затем относительно **текущей рабочей папки**
> (`resources/`). Поэтому `solver` можно запускать из любого каталога —
> в том числе двойным щелчком в `build\` или через проводник. Если
> копируете `solver.exe` в другое место, скопируйте рядом `arial.ttf`,
> `consola.ttf` и `mai.png`.

После запуска открывается окно размером **1200×890** с заголовком
«Solver piecewise linear route».

## 2. Общий вид окна

```
+--------------------------------+---------------------------------+
|  ПОЛЕ (карта) 600×600 px       |  RMB/LMB - raise/lower...       |
|                                |  [ Max difference slider ]      |
|   ● Start  (красный)           |  [ Max angle slider        ]    |
|   ● End    (синий)             |  x: ...   y: ... | 0≤x<150      |
|   ● Turn1.. (зелёные)          |  path difficulty: ...           |
|                                |  [ Print way ]                  |
|                                |  таблица точек и углов          |
+--------------------------------+---------------------------------+
| [Add turns] [Remove turns] [Save config]                        |
| [Generate grid] [Load grid] [Load config]                       |
| [Change grid]  [имя файла карты] [имя файла конфигурации]        |
| [DP Method] [Full Walk Method]                                  |
+----------------------------------------------------------------+
| Time: ...  Done: ...   (прогресс расчёта, внизу)                |
+----------------------------------------------------------------+
```

Координаты ниже указаны в пикселях окна (начало координат — левый
верхний угол; ось Y направлена вниз). Реальные кнопки чуть шире подписи,
поэтому положение — это координата **верхнего левого угла** кнопки.
Область справа от поля (x ≈ 615…1075) — панель параметров и информации.

## 3. Поле и маркеры

Поле — прямоугольник **600×600 px**. По умолчанию это сетка **150×150**
ячеек (размер ячейки 4 px). Маркеры:

| Маркер | Цвет | Роль |
|---|---|---|
| **Start** | красный | стартовая точка маршрута |
| **End** | синий | конечная точка маршрута |
| **Turn1, Turn2, …** | зелёный | промежуточные точки поворота |

Действия с маркерами:

| Действие | Как сделать |
|---|---|
| Переместить маркер | нажать ЛКМ по маркеру и вести мышь (точка притягивается к центру ячейки) |
| Добавить поворот | кнопка **Add turns** (новая точка появляется в центре поля) |
| Удалить поворот | кнопка **Remove turns** — удаляет последний поворот |
| Удалить поворот «мышью» | перетащить зелёную точку **за пределы поля**, затем кликнуть вне поля |
| Старт/конец удалить нельзя | только повороты |

> **Важно для поиска.** В маршруте должен быть **хотя бы один поворот**
> (кнопка **Add turns**), и все маркеры должны находиться **внутри поля**.
> Иначе кнопки «DP Method» / «Full Walk Method» молча не запускают расчёт.

Координаты клетки: **x** — столбец (слева направо, 0..gridSize.x-1),
**y** — строка **снизу вверх** (ось Y перевёрнута: на экране y=0 сверху,
в интерфейсе y = gridSize.y-1 минус номер экранной строки). Текущее
положение мыши в этих координатах показывается в панели справа.

## 4. Слайдеры

| Слайдер | Где | Диапазон | Что делает |
|---|---|---|---|
| **Max difference** | справа, y≈95 | 0 … 0.2 | максимально допустимая разница между соседними клетками поля при редактировании рельефа |
| **Max angle** | справа, y≈165 | 0 … 90° | максимально допустимый угол поворота в каждой точке излома |
| **Вертикальный мультислайдер** | справа, x≈1075 | 0 … 1 | индикатор значений поля: зелёный — под курсором, красный — в Start, синий — в End (только отображение) |

Как пользоваться слайдерами: нажать ЛКМ на полосе и, не отпуская,
двигать мышь; значение обновляется в реальном времени. Отпускание —
завершение.

## 5. Кнопки

| Кнопка | Положение | Назначение |
|---|---|---|
| **Add turns** | низ, (15, 615) | добавить промежуточный поворот в центр поля |
| **Remove turns** | низ, (178, 615) | удалить последний промежуточный поворот |
| **Save config** | низ, (450, 610) | сохранить текущее состояние (поле + параметры + маршрут) в файл из поля «имя файла конфигурации» |
| **Generate grid** | низ, (15, 670) | сгенерировать поле из встроенной функции рельефа `myFunction()` |
| **Load grid** | низ, (230, 670) | загрузить карту из изображения, имя которого введено в поле «имя файла карты» |
| **Load config** | низ, (450, 670) | загрузить состояние из файла из поля «имя файла конфигурации» |
| **Change grid** | низ, (15, 730) | переключатель режима редактирования рельефа (вкл/выкл) |
| **DP Method** | низ, (15, 770) | найти оптимальный маршрут динамическим программированием |
| **Full Walk Method** | низ, (193, 770) | найти оптимальный маршрут полным перебором с ограничением области |
| **Print way** | справа, (615, 275) | вывести текущий маршрут и его стоимость в консоль |

Кнопки **Method 1** и **Experiment** в текущей сборке **скрыты** (не
отрисовываются и не обрабатываются) — в коде сохранены запасные методы.

Во время расчёта кнопка метода окрашивается в красный цвет, а внизу окна
обновляется прогресс **Time / Done** (или «Remains: … sides, … levels»
для полного перебора). Окно остаётся отзывчивым, закрыть его можно в
любой момент (расчёт прерывается).

## 6. Текстовые поля (ввод имён файлов)

| Поле | Где | Для чего |
|---|---|---|
| «Имя файла карты» | (230, 725), размер 200×30 | имя изображения для **Load grid** |
| «Имя файла конфигурации» | (450, 725), размер 200×30 | имя файла для **Save config** / **Load config** |

Правила ввода:

- кликнуть по полю — активировать ввод (появляется курсор);
- печатать **латиницей, цифрами и символами** (кириллица в поле искажается);
- `Backspace` — удалить символ слева; `Delete` — справа;
- `←` / `→` — переместить курсор; `Home` / `End` — в начало/конец;
- `Ctrl+V` — вставить из буфера обмена;
- клик вне поля — завершить ввод.

Для **Load grid** и **Load config** путь указывается относительно рабочей
папки запуска (например, `maps/1.png`). Если файл не найден, программа
ничего не делает — сообщение об ошибке не выводится.

## 7. Редактирование рельефа (инструмент «кисть»)

1. Включить переключатель **Change grid** (индикатор станет зелёным).
2. Удерживать **ЛКМ** над полем — поднимать рельеф; **ПКМ** — опускать.
3. Двигать слайдер **Max difference**, меняя «жёсткость» ограничения:
   при перетаскивании соседние клетки автоматически подгоняются так,
   чтобы разница не превышала заданную.
4. Выключить **Change grid**, чтобы вернуться к навигации/маркерам.

Значение поля под курсором видно на вертикальном мультислайдере
(зелёная метка) и в строке «path difficulty» — для текущего маршрута.

## 8. Информационные панели

| Панель | Что показывает |
|---|---|
| Сверху справа | подсказка «RMB/LMB — raise/lower the place», текущие **Max difference** и **Max angle** |
| `x: … y: …` | координаты клетки под курсором |
| `0 ≤ x < …  0 ≤ y < …` | размеры текущей сетки |
| `path difficulty: …` | стоимость текущего маршрута (сумма значений поля вдоль звеньев) |
| Таблица «name point angle» | список точек маршрута: имя, координаты, угол поворота в каждой точке |
| Внизу слева | время расчёта и прогресс (Done % или Remains) |

## 9. Консоль

При запуске из консоли программа выводит результаты:

- **Print way** — текущий маршрут и стоимость, например:

  ```
  start: ( 32,  22)
  turn1: ( 96,  20) 46.78
  turn2: (125,  49) 47.64
  end:   (122, 114)
  path difficulty: 93.635
  ```

- **Full Walk Method** — по завершении:

  ```
  Optimal solution found by Method 2 in 1.04047 seconds with path difficulty 93.635
  ```

- **DP Method** — по завершении:

  ```
  dp = 93.635
  Optimal solution found by DP Method in 0.86 seconds.
  ```

## 10. Примеры работы

### Пример 1. Базовый маршрут (генерация + поиск)

1. Запустить `solver`.
2. Нажать **Generate grid** — поле заполнится синтетическим рельефом.
3. Нажать **Add turns** (один или два раза) — появятся зелёные повороты.
4. При необходимости перетащить Start/End в удобные точки внутри поля.
5. Нажать **Full Walk Method** — маркеры перестроятся в оптимальную
   ломаную, внизу появится прогресс, в консоли — результат.
6. Нажать **Print way** — посмотреть координаты и стоимость.

### Пример 2. Ограничение угла поворота

1. Выполнить шаги 1–3 из примера 1.
2. Передвинуть **Max angle** на 30° (маленький радиус поворота).
3. Нажать **DP Method** — сравнить «path difficulty» с вариантом 60°.
4. Увеличить угол до 90° — маршрут станет «свободнее», стоимость обычно
   снижается. Чем меньше угол, тем длиннее и извилистее путь.

### Пример 3. Свой рельеф

1. Включить **Change grid**.
2. Удерживая ЛКМ, «нарисовать» гору; ПКМ — впадину.
3. Установить **Max difference** ≈ 0.05 — рельеф сгладится у границы
   «горы»; уменьшить до 0.01 — сглаживание станет шире.
4. Выключить **Change grid**, добавить повороты и запустить поиск.
5. Обратите внимание: «path difficulty» на панели отражает изменение.

### Пример 4. Карта из файла

1. Ввести в поле «Имя файла карты» `maps/1.png` (относительно корня).
2. Нажать **Load grid** — размер сетки возьмётся из изображения.
3. Маркеры Start/End окажутся в правом нижнем углу — перетащите их
   внутрь карты (см. панель `0 ≤ x < …`).
4. Добавить повороты (**Add turns**) и запустить **Full Walk Method**.

### Пример 5. Сохранение и восстановление состояния

1. Построить поле и маршрут, ввести в поле «Имя файла конфигурации»
   `test.cfg`.
2. **Save config** — состояние записывается в файл.
3. Изменить что-нибудь (сгенерировать поле заново, подвигать точки),
   затем **Load config** — вернутся сохранённые параметры.

> **Ограничение (см. раздел 12):** в текущей версии загрузка конфигурации
> корректно работает, только если размер сетки в файле совпадает с
> текущим (150×150), а после загрузки поле на экране не перерисовывается
> и не пересчитываются вспомогательные данные; это известный баг.

## 11. Формат файла конфигурации (для справки)

Файл `test.cfg` (текстовый, значения через пробел):

```
gridSize.x  gridSize.y  cellSize  fieldSize.x  fieldSize.y
значения сетки: сначала по всем x для y=0, затем y=1, … (float)
start.x  start.y  end.x  end.y          # пиксельные координаты маркеров
число поворотов n
turn1.x turn1.y  turn2.x turn2.y  …     # n пар
maxDifference  phi_0                    # параметры слайдеров
```

Пример фрагмента из `test.cfg`:

```
150 150 4 600 600 0.413629 0.426108 … (22500 значений) …
130 510 490 142 3 214 542 454 482 530 254 0.0249868 60
```

здесь Start (130,510), End (490,142), три поворота, maxDifference ≈ 0.025,
phi_0 = 60°.

## 12. Известные ограничения и найденные баги

- **Load config** не перерисовывает поле и не пересчитывает префиксные
  суммы для интеграла; при размере сетки, отличном от текущего, возможен
  выход за границы массива (`source/app.h`, `App::loadConfig`).
- **ПКМ понижает рельеф даже при выключенном Change grid** — из-за
  приоритета операторов в `source/app.h` (`eventHandler`, условие
  обновления поля). Ожидаемое поведение — только при включённом режиме.
- В **TextBox** искажается ввод кириллицы — используйте латиницу.
- Шрифты и иконка ищутся рядом с исполняемым файлом, затем относительно
  рабочей папки (`resources/`); при сборке CMake копирует их в `build/`.
  Если `solver` запущен из другого каталога без этих файлов рядом —
  текст может отсутствовать.
- Кнопки **Method 1** и **Experiment** скрыты; соответствующие методы
  оставлены в коде, но к интерфейсу не подключены.
- Для поиска нужен минимум один поворот, иначе расчёт не запускается.
- Расчёты выполняются в фоновых потоках; при закрытии окна во время
  расчёта поток прерывается принудительно (может повлиять на
  стабильность), это ограничение текущей реализации.
